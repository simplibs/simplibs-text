# ⚙️ `actions` — Pipeline Steps for Text

The `actions` package turns every function of the library that takes **a text and returns one
result** into an `Action` from [`simplibs-actions`](https://pypi.org/project/simplibs-actions/). An
action is the function with its options bound in advance: constructed once, then called with the one
value that changes — the text — which is what makes steps chainable into a pipeline.

```python
import re
from simplibs.text.actions import RemoveMatches, KeepLineRange, AddLineNumbers, Truncate
from simplibs.text.presets import COMPACT

strip_comments = RemoveMatches(pattern=re.compile(r"#.*")) >> COMPACT
strip_comments("x = 1  # c\n# n\n\ny = 2\n")      # -> 'x = 1\ny = 2\n'

preview = KeepLineRange(start=2, end=5) >> AddLineNumbers(start=2) >> Truncate(max_lines=2)
preview("l1\nl2\nl3\nl4\nl5\nl6\n")             # -> '2: l2\n3: l3\n… (truncated)'   lines 2-5, numbered from 2, at most 2 of them

await preview.acall(text)                          # the same, off the event loop
```

Actions are **not** exported from `simplibs.text` itself — they are a domain of their own, imported
through `simplibs.text.actions`, which defines `__all__`. **Thirty actions in six groups**, one for
every function except the two [recipes](logic/README_TEXT_RECIPES.md) (whose counterparts are the
[presets](README_TEXT_PRESETS.md)): **remove**, **keep**, **replace**, **decorate**, **clean** and
**case**.

## How an action is built and called

Each action is generated by `create_action` from its function. The **text** is the *main input*;
**every other parameter** becomes a keyword-only *constructor option*.

```python
action = RemoveMatches(pattern="# TODO")      # options
action("a # TODO\nb\n")                       # main input -> 'a \nb\n'
```

* **Constructor options are validated** by the same annotations as the function's parameters — a
  wrong type or value is a `ValidationError` at construction (`KeepLineRange(start=0)`). A *missing
  required* option is a plain `TypeError` (`RemoveMatches()`).
* **The main input is validated** when the action is called.
* **Errors raised by the function surface unchanged** — an action adds no layer of its own
  (`TEXT_PATTERN_FLAGS_CONFLICT`, `TEXT_TRUNCATE_LIMIT_MISSING`, ...).
* **The class docstring is the function's docstring**, and `_input_type` / `_output_type` expose the
  annotations for tooling.

## One direction only

`simplibs-file` offers two directions for its writers (the path flows, or the content flows) because a
writer has two things to carry. A text step has **one**: the text flows, and the pattern, the limit
or the prefix is configuration. There are no `…To` siblings here.

## Composition

```python
step_a >> step_b          # run step_b on the result of step_a      (a flat sequence)
step_a & step_b           # run both on the same input              -> (result_a, result_b)
step_a | fallback_step    # run fallback_step if step_a raises
```

A chain of text steps is itself a step, so it can be named once and reused — that is exactly what the
two [presets](README_TEXT_PRESETS.md) are:

```python
naming = ToSnakeCase() >> Indent(prefix=4)
naming("MyVarName\nOtherName\n")                   # -> '    my_var_name\n    other_name\n'
```

A `Rule` from `simplibs-rules` is a valid step on either side (`guard`), which is how a condition
meets a text step without any condition inside it.

## Async

All thirty actions are synchronous, so `await action.acall(text)` runs them in a worker thread
(`asyncio.to_thread`), and a whole pipeline can be awaited the same way.

## What is not here

* **`cleanup_whitespace` and `compact`** — their counterparts are the presets `CLEANUP_WHITESPACE`
  and `COMPACT`, built from the actions of `remove`.
* **Rules and predicates** — a `bool` is not a text; combine the actions with the rules of
  `simplibs-rules`.

The actions over [`logic/remove`](logic/README_TEXT_REMOVE.md). Each is the function with its options bound in advance; the text flows through.

### `RemoveSpans`

Wraps [`remove_spans`](logic/README_TEXT_REMOVE.md#remove_spans) — cuts given character ranges out of the text.

**Constructor options:**

* `spans` (*Sequence[Span]*, required): [`Span`](README_TEXT_ANNOTATIONS.md#span) pairs `(start, end)`, half-open, any order; overlapping spans are merged.
* `drop_emptied_lines` (*bool*, default `True`): A line that is blank only because of the removal disappears whole.

**Main input:** the text (`str`). **Returns:** `str`.

**Example usage:**

```python
RemoveSpans(spans=[(0, 6)])("hello world")    # -> 'world'
```

**Notes.** Mostly used behind a step that **finds** the positions — a parser or a tokenizer — rather than with a hand-written list.

<details>
<summary>🔍 Under the hood</summary>

```python
RemoveSpans = create_action(remove_spans, main_param="text", class_name="RemoveSpans")
```

The options of `remove_spans` become keyword-only constructor options; the text is the main input.

</details>

# Replace

The actions over [`logic/replace`](logic/README_TEXT_REPLACE.md). Each is the function with its options bound in advance; the text flows through.

### `ReplaceMatches`

Wraps [`replace_matches`](logic/README_TEXT_REPLACE.md#replace_matches) — replaces the matches by a text or by a function's result.

**Constructor options:**

* `pattern` (*Pattern*, required): What to look for: a literal `str`, a compiled `re.Pattern`, a `Regex` tree or a `RegexPattern` ([`Pattern`](README_TEXT_ANNOTATIONS.md#pattern)).
* `replacement` (*Replacement*, required): A literal `str`, or a function from the `re.Match` to a `str` ([`Replacement`](README_TEXT_ANNOTATIONS.md#replacement)).
* `flags` (*int*, default `0`): `re` flags; not allowed together with a compiled pattern.
* `count` (*int_non_negative*, default `0`): How many matches to replace; `0` means all.

**Main input:** the text (`str`). **Returns:** `str`.

**Example usage:**

```python
ReplaceMatches(pattern="a.b", replacement="-")("a.b aXb")    # -> '- aXb'
ReplaceMatches(pattern=re.compile(r"\w+"), replacement=lambda m: m.group(0).upper())("hello world")    # -> 'HELLO WORLD'
```

**Notes.** A `str` replacement is literal (`"\1"` is not a group reference); pass a function when you need the groups.

<details>
<summary>🔍 Under the hood</summary>

```python
ReplaceMatches = create_action(replace_matches, main_param="text", class_name="ReplaceMatches")
```

### `SplitWords`

Wraps [`split_words`](logic/README_TEXT_CASE.md#split_words) — splits the text into its words (a `list[str]`).

**Constructor options:** none.

**Main input:** the text (`str`). **Returns:** `list[str]`.

**Example usage:**

```python
SplitWords()("myVarName")    # -> ['my', 'Var', 'Name']
```

**Notes.** The one action whose result is not a text. It ends a text pipeline; follow it with a function of your own, or use `ForEach` from `simplibs-actions` to treat the words one by one.
